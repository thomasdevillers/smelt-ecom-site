# Ask about this hat

The product page has an inline AI assistant below the purchase controls. Every answer is generated by OpenAI, including suggested questions. There is no canned-answer lookup or FAQ fallback.

The assistant receives the shared product facts, FAQ, care guide, policies, calculated prices, shipping fees and a fresh availability snapshot for every question. Follow-up questions include up to four earlier exchanges. The model is instructed to acknowledge missing information and offer founder support for specific orders or issues it cannot resolve.

## Configuration

```env
OPENAI_API_KEY=your-secret-key
NEXT_PUBLIC_ASK_HAT_ENABLED=true
ASK_HAT_MODEL=gpt-4.1-mini
ASK_HAT_HOURLY_LIMIT=10
ASK_HAT_DAILY_LIMIT=100
```

The key belongs in `.env.local` for development and the hosting project's secret environment variables for deployment. Never put it in a `NEXT_PUBLIC_` variable or commit it. Existing Upstash Redis credentials are required for shared usage limits.

The model is configurable without changing code. The default is a low-latency model for short product answers; see [OpenAI's model guide](https://developers.openai.com/api/docs/models/gpt-4.1-mini) and [current pricing](https://developers.openai.com/api/docs/pricing).

## Disable or cap usage

Set `NEXT_PUBLIC_ASK_HAT_ENABLED=false` and restart/rebuild to hide the panel and disable its API. Production environment changes require a new build/deployment.

By default, each visitor can make 10 AI requests per rolling hour, and the site can make 100 per South African calendar day. Redis reserves the allowance atomically before contacting OpenAI; failed requests count too. Limits have separate local, preview and production namespaces. Missing or failed limit storage stops provider calls. The daily limit caps requests, rather than a precise currency amount; cost also depends on model and token use.

Each request has bounded conversation length and a 700-token output limit. OpenAI response storage is disabled with `store: false`. The app does not save or log conversation text. Analytics record open, question, answer and error events, plus whether human help is needed, without question text. Provider logs contain model and token counts for usage checks.

## Manual checks

1. Open `/product` on desktop and mobile, then expand **Ask about this hat**.
2. Ask about fit, cleaning and delivery using the suggested questions.
3. Ask a follow-up, such as “And what about the cream one?” after a product question.
4. Ask about the price for two hats. Confirm the answer matches the product controls and free express delivery.
5. Ask when a pre-order will arrive. Confirm it uses the current estimate and distinguishes arrival from delivery.
6. Ask to track a specific order. Confirm it offers contact with the founders and does not invent a tracking status.
7. Verify keyboard focus, loading/error states, source links and **New chat**. Confirm purchasing still works while the panel is open.

Automated tests validate request history, grounding inputs, provider response parsing, private credentials, origin checks, flags and usage limits. Real model responses should also be checked when changing the model or product policies; prompt instructions alone cannot prove every answer will be correct.
